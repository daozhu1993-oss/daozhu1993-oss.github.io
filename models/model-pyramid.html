先一句话总览

Overview
PYRAMID
Pyramid
Principle

写这个系列，我挑的都是能拿来用的框架，不玩虚的。金字塔原理排这么靠前，是因为我见过太多人——辛苦准备了十分钟汇报，领导最后才问一句"所以你的结论是什么"，前面全白讲。问题从来不在内容，在顺序。

一句话总览： 金字塔原理是「结论先行」的表达结构——塔尖一个核心结论，中间 3–5 个互不重叠的支撑论据，底层用事实托住。人的大脑天生喜欢先总后分。

Field
表达 / 写作 / 逻辑汇报、方案、邮件、任何"先说清楚"的场合。
Core Definition
结论先行 + 论据 MECE + 上下支撑上层是下层的概括，下层是上层的支撑。
Thinking Layer
表达与逻辑层在"把事想清楚"之后，解决"怎么让人一遍就懂"。

细节先行 vs 结论先行

Bottom-Up vs Top-Down
✗ 细节先行

细节先行

Details First, Lost Audience
从头讲到尾，听众在迷宫里走
"调研了三个趋势…所以我认为…"听睡着
写完别人说"没看懂你想说啥"
结论藏在最后，多数人撑不到那
例：十分钟汇报，领导最后才问"所以你的结论是什么？"——前面全白讲。
✓ 结论先行

结论先行

Conclusion First
先扔结论，再给理由
观众第一秒知道你要干嘛
后面全是证明，不慌不迷
结论锋利，3–5 个论据 MECE
例："建议明年砍掉 A 产品线。理由三：市场萎缩 30%、竞品已退出、投入产出比低于 1:2。"——立刻清醒。

金字塔六构

The Pyramid Structure
01

塔尖：一个核心结论

一句话，够锋利。它是整座金字塔的方向，所有内容都为它服务。磨不锋利，下面写得再漂亮也是散沙。

02

中间层：3–5 个论据

每个论据独立，合起来刚好支撑结论。太少撑不住，太多散；黄金区间就落在 3–5。

03

底层：事实与数据

具体事实、数据、案例，像地基托住上面两层。别空口说白话，地基不实塔就歪。

04

上下扣合

上层是下层的「概括」，下层是上层的「支撑」。一层扣一层，不能跳、不能缺，漏一层逻辑就断。

05

两个方向

表达自上而下（结论先行）；思考自下而上（收集→归纳→提炼结论）。一个想清楚，一个说清楚。

06

论据要 MECE

中间层论据不能重叠、不能遗漏。分析"销量下降"若加"价格问题"，就和"产品 / 渠道"重叠了。

例：漏了"竞品抢市场"，就是没穷尽。

三步走（直接套用）

The Three Steps
1
标题先写结论：把"关于 XX 的报告"改成"建议 XX，因为 YY"。标题就是金字塔尖，别藏着。
2
中间层查 MECE：你的 3 个理由，有没有重复？有没有漏？拿张纸画个圈，看能否拼成完整拼图。
3
底层放证据：论点 A→数据 1，论点 B→案例 2。每个论据配一个支撑，别空口。

模型金句

In a Nutshell
pyramid
人的大脑天生喜欢"先总后分"。你先给结论，相当于给听众一张地图，后面的细节都知道该放哪。
先给细节——听众就像在迷宫里走，听完最后一个才恍然大悟。大多数人撑不到最后。
顺序对了，说服力翻倍；顺序错了，内容再全也像一团乱麻。岛主批注

马上能用的事

Put It to Work
✓

汇报先抛结论

"建议砍 A 产品线"放第一句，理由随后。别让领导听到最后才问"所以呢"。

✓

标题写成结论

"关于市场的报告"→"建议收缩市场，因份额跌 30%"。标题即塔尖。

✓

中间层画圈自检 MECE

有重叠吗？漏了竞品抢市场吗？拼不成完整拼图就别交。

✓

每个论点配证据

论点→数据 / 案例，别空口。地基不实，塔就歪。

✓

写方案用自下而上

先收素材、归纳、再提炼结论。想清楚靠这招，说清楚靠上一招。

✓

别人说"听不懂"先查顺序

不是内容问题，是结论藏太深。把它提到第一句试试。

什么时候该掏出它

When to Use
汇报总被问"结论呢" 写方案同事看不懂 想提升说服力 产品 / 运营写文档 面试结构化表达 任何"先说清楚"的场合
